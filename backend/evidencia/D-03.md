# D-03 — Verificación desde la URL pública

Fecha: 2026-11-08  
URL: `https://libreria.enzogiaquinta.me`  
Objetivo: demostrar que el backend desplegado responde desde afuera y que una
venta real funciona.

## Comandos y salidas

```text
GET /health/ready   -> 200 {"status":"ok"}
GET /health/live    -> 200 {"status":"ok"}
GET /libros/        -> 200 catálogo del seed
```

Venta real:

```json
{"cliente_id":1,"renglones":[{"libro_id":4,"cantidad":1}]}
```

```text
POST /ventas/ -> 201
id: 4
total: "27000.00"
libro_id: 4
cantidad: 1
```

Stock antes/después de `libro_id=4` (Respiración artificial):

```text
antes:  3
después: 2
```

Prueba de stock insuficiente:

```json
{"cliente_id":1,"renglones":[{"libro_id":5,"cantidad":2}]}
```

```text
POST /ventas/ -> 409
{"detail":"Stock insuficiente para 'Bestiario'"}
```

## Lectura

La API está pública y healthy, el catálogo del seed se lee, la venta responde
201 con precios y total del servidor, el stock baja en la misma transacción y el
409 por stock insuficiente no escribe la venta.

## Verificación de cierre C-21 — 2026-11-08 19:08 UTC-3

Comprobación desde fuera del VPS, sin repetir el `POST` para no alterar el stock
de referencia de D-04:

```text
GET /health/ready   -> 200 (15 bytes)
GET /health/live    -> 200 (15 bytes)
GET /libros/        -> 200 (1118 bytes); libro 4, stock 2
GET /ventas/4       -> 200
```

Extracto real de `GET /ventas/4`, que confirma el precio copiado por renglón y
el total calculado (`RN-10`):

```json
{"id":4,"fecha":"2026-11-08T20:26:19.108460Z","total":"27000.00",
 "renglones":[{"libro_id":4,"cantidad":1,"precio_unitario":"27000.00",
 "subtotal":"27000.00","titulo":"Respiración artificial"}]}
```

- La venta 4 quedó registrada a las **17:26:19 UTC-3** (`20:26:19Z`), antes de
  esta verificación: el servicio ya estaba en línea.
- `precio_unitario` = `27000.00`, `subtotal` = `27000.00`, `total` = `27000.00`:
  el servidor copió el precio del libro y calculó el total.
- El `POST /ventas/` 201 de la corrida de arriba es la evidencia de creación; no
  se repitió para conservar `libro_id=4` con stock 2, el dato de referencia de
  D-04.
- Reconfirmación al cierre de la sesión, **19:20 UTC-3**: `GET /health/ready` 200
  y `GET /libros/` 200; el despliegue siguió en línea después de todos los
  cambios documentales.
