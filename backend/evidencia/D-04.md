# D-04 — Persistencia tras reinicio

Fecha: 2026-11-08  
Host: VPS de EasyPanel (`root@srv1930369`)  
Objetivo: demostrar que reiniciar el contenedor no pierde datos y que Alembic
sigue en head.

## Comandos

```bash
CID=$(docker ps --filter name=libreria-api --filter status=running -q | head -n1)
docker restart "$CID"
sleep 20
CID=$(docker ps --filter name=libreria-api --filter status=running -q | head -n1)
docker inspect "$CID" --format '{{.State.Status}} | {{if .State.Health}}{{.State.Health.Status}}{{end}}'
docker exec "$CID" python -m alembic current
curl -s -o /dev/null -w 'health=%{http_code}\n' https://libreria.enzogiaquinta.me/health/ready
```

## Salida real

```text
running | healthy
5f67a857f685 (head)
health=200
```

## Lectura

El reinicio no destruye la base (vive fuera del contenedor), el contenedor vuelve
a quedar healthy y la versión de Alembic sigue en head. La URL pública responde
200 después del reinicio.

## Equivalencia EasyPanel: alcance parcial

- El contenedor que se reinició es el que **gestiona EasyPanel**
  (`libreria-api`, puerto 8000). El reinicio se hizo con `docker restart "$CID"`
  sobre ese contenedor; **no** se usó el botón Restart/Recreate de EasyPanel ni
  un `docker rm -f` + `docker run`.
- **El `docker run` literal de la consigna no se ejecutó.** Tampoco se creó un
  contenedor one-off (`libreria-c21`) en un puerto alternativo: por eso no hay
  uno que eliminar.
- Por lo tanto D-04 es una **equivalencia parcial**: demuestra que el estado
  vive en la base y que reiniciar no repite migraciones, pero no demuestra el
  reemplazo completo del contenedor ni el comando literal. La diferencia se
  declara también en `DEPLOY.md`.

## Verificación de cierre C-21 — 2026-11-08 19:08 UTC-3

Después del reinicio, desde fuera del VPS:

```text
GET /health/ready  -> 200
GET /libros/       -> 200; libro 4 (Respiración artificial) stock 2
GET /ventas/4      -> 200; precio_unitario 27000.00, total 27000.00
```

- El stock 2 de `libro_id=4` es el mismo valor que dejó la venta 4 de D-03
  (`3 → 2`): el dato persistió al reinicio.
- La venta 4 y su renglón siguen legibles después del reinicio.
- La revisión de Alembic sigue en `5f67a857f685 (head)` (salida de arriba):
  `alembic upgrade head` vuelve a correr en el arranque pero no aplica nada
  porque la base ya está en head.
